# Онлайн-деканат

## Быстрый запуск

Самый простой способ запустить приложение — через Docker Compose. Установите и запустите Docker Desktop, откройте PowerShell в корневой папке проекта (рядом с `compose.yaml`) и выполните:

```powershell
docker compose up --build -d
```

После сборки откройте интерфейс: <http://localhost:8000/ui>. Проверить состояние сервера можно по адресу <http://localhost:8000/health>. Чтобы посмотреть журнал запуска, выполните `docker compose logs -f web`; для остановки — `docker compose down`.

Для запуска без Docker на Windows используйте `setup.bat`; подробные шаги приведены в разделе [«Установка и запуск в Windows»](#установка-и-запуск-в-windows). Настройка почты и создание учетной записи администратора описаны в разделе [«Запуск через Docker Compose»](#запуск-через-docker-compose).

Локальный помощник для проверки студенческих документов. Приложение принимает файл и вопрос на русском языке, распознаёт документ, извлекает известные поля и сверяет их с локальным Положением. Результат включает ответ, найденные поля и источники проверки.

OCR и логика проверки выполняются на компьютере пользователя: приложение не отправляет документы во внешние API. Для распознавания доступны PaddleOCR, EasyOCR и Tesseract. Режим `auto` последовательно пробует эти движки; для демонстрации и тестов доступен режим чтения текста из `.txt`. Установщик Windows и Docker-образ включают Tesseract с русским и английским языками, поэтому основной сценарий распознавания работает локально после установки.

> Установка загружает библиотеки Python, Tesseract и его языковые данные. PaddleOCR и EasyOCR остаются дополнительными движками: их модели могут загружаться при первом распознавании и занимают много места.

## Возможности

- Приём сканов и изображений `JPG`, `PNG`, `WEBP`, `BMP`, `TIFF`, а также PDF размером до 16 МБ.
- Определение типа документа по тексту либо явный выбор типа в CLI/API:
  - `study_certificate` — справка об обучении;
  - `academic_leave_application` — заявление на академический отпуск;
  - `practice_certificate` — справка о практике.
- Извлечение полей, перечисленных в `config/document_types.json`.
- Сопоставление вопроса с правилами из `config/regulations.json`.
- Веб-интерфейс, HTTP API и командная строка.
- Онлайн-чат посетителя с сотрудниками: обновления в реальном времени, отправка OCR-ответа в поле сообщения и зашифрованное хранение вложений.
- Отдельный кабинет сотрудника (`/staff`) с мгновенными обновлениями чатов, сигналом новых обращений, звуковыми и системными уведомлениями браузера.
- Вход сотрудников с ролями администратора и сотрудника; администратор создает учетные записи из рабочего места.
- Шифрование получаемых через API файлов при хранении; расшифрованный временный файл удаляется после обработки.
- Зашифрованная SQLite-база студентов и документов (`data/students.db`); имя студента и поля хранятся в Fernet-зашифрованных payload, а не открытым текстом.
- Автоматическая оценка качества снимка (разрешение, освещённость, контраст и резкость) с увеличением, улучшением контраста и резкости плохих фото перед OCR.
- Автоматическое исправление поворота страницы перед OCR; поиск подписи и печати использует ту же ориентацию страницы.
- Подсветка фрагментов карточки, найденных OCR; для подписи и печати выделяются сами рукописные/графические следы, а не печатные слова-маркеры.
- Журнал ответов для сдачи в `results.json` без дублирования ФИО и распознанного текста.
- Локальная обработка без внешних API.
- Адаптивный интерфейс кабинета для компьютеров, телефонов и узких экранов.

Схема полей соответствует трём типам документов из задания:

| Справка об обучении | Заявление на академический отпуск | Справка о практике |
| --- | --- | --- |
| ФИО студента | ФИО студента | ФИО студента |
| Название вуза | Группа | Организация |
| Направление подготовки | Причина отпуска | Дата начала практики |
| Форма обучения | Дата начала отпуска | Дата окончания практики |
| Начало периода обучения | Дата окончания отпуска | Руководитель практики |
| Окончание периода обучения | Курс | Оценка |
| Номер справки; дата выдачи | Дата заявления | Номер справки; дата выдачи |
| Подпись; печать (есть/нет) | Подпись студента (есть/нет) | Оценка; подпись; печать (есть/нет) |

В карточках справок номер и дата выдачи отображаются отдельными полями. Начало и окончание периода обучения, а также даты начала и окончания практики извлекаются и показываются раздельно.

## Требования

- Windows 10/11 для `setup.bat`; нужен Python 3.11 или новее.
- Интернет нужен для установки библиотек, Tesseract и языковых данных. При стандартной установке сетевые загрузки не требуются во время распознавания.
- PaddleOCR, EasyOCR и датасет устанавливаются отдельно; они могут обращаться к внешним источникам и занимать несколько гигабайт.

## Запуск через Docker Compose

Нужен установленный Docker Desktop (Windows/macOS) или Docker Engine с Compose plugin (Linux). Контейнер включает FastAPI-приложение и Tesseract с русским и английским языками. Модели PaddleOCR и EasyOCR не устанавливаются, поэтому при стандартном запуске распознавание не обращается к внешним источникам.

Почтовый сервер настраивается через переменные окружения SMTP и подходит для любого SMTP-провайдера. Чтобы настроить почту, создайте файл `.env` в корневой папке проекта и укажите SMTP host, порт, логин/пароль (если требуются) и адрес отправителя. Для порта 587 обычно используют STARTTLS, для порта 465 — SSL. Не публикуйте `.env` и не добавляйте его в систему контроля версий.

Сначала соберите образ, чтобы создать администратора из того же образа и Docker volume:

```bash
docker compose build
```

### Чат и учетные записи сотрудников

Создайте первого администратора один раз. Введите его корпоративную почту; система сгенерирует криптографически стойкий временный пароль и отправит его почтой. Пароль можно сменить в профиле:

```powershell
docker compose run --rm --entrypoint online-dekanat web create-admin
docker compose up --build -d
```

Сотрудники могут зарегистрироваться самостоятельно с любым корректным адресом электронной почты. При регистрации система сразу создает аккаунт и отправляет на указанный адрес криптографически случайный временный пароль; смена временного пароля необязательна, его можно поменять в профиле. В базе пароль хранится только в виде scrypt-хеша. Администратор также может пригласить сотрудника по почте из панели; для приглашенного аккаунта временный пароль отправляется сразу.

**Более простой вариант — Brevo:** создайте аккаунт, подтвердите адрес отправителя и создайте API-ключ. Укажите в `.env` только эти параметры; SMTP-порт, пароль приложения и TLS настраивать не нужно:

```dotenv
BREVO_API_KEY=ваш_api_ключ
BREVO_SENDER_EMAIL=подтвержденный_адрес_отправителя
BREVO_SENDER_NAME=Онлайн-деканат
```

Brevo отправляет письма на адреса любых почтовых сервисов. Адрес отправителя должен быть подтвержден в Brevo. API-ключ храните только в локальном `.env`, не публикуйте его. Если параметры Brevo заданы, приложение использует API; SMTP остается необязательным запасным способом:

```dotenv
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_USERNAME=account@example.org
SMTP_PASSWORD=пароль_или_ключ_приложения
SMTP_FROM=dekanat@example.org
SMTP_STARTTLS=true
SMTP_SSL=false
```

При использовании порта 465 задайте `SMTP_SSL=true` и `SMTP_STARTTLS=false`. При необходимости можно использовать SMTP без аутентификации, оставив `SMTP_USERNAME` и `SMTP_PASSWORD` пустыми.

Сотрудники входят через кнопку «Вход сотрудника», отвечают на обращения и прикладывают файлы. Посетители могут писать через виджет «Написать сотруднику», прикреплять файлы и нажимать «Вставить ответ в чат» под результатом OCR. Вложения и переписка шифруются при хранении в SQLite и `app_data`; загружать можно файлы до 20 МБ разрешенных форматов. Для аудита каждое обращение также записывается в отдельный JSON-файл с восьмизначным кодом обращения в имени (например, `eba0063a.json`). JSON-журналы содержат сообщения в открытом виде, поэтому ограничьте доступ к каталогу журналов. По умолчанию он находится в `/app/data/conversations` внутри volume `app_data`; каталог можно переопределить переменной `ONLINE_DEKANAT_CHAT_LOG_DIR`.

Сессия хранится в подписанной HttpOnly cookie с временем жизни 12 часов. Секрет автоматически создается в `app_data` и сохраняется между перезапусками; задавать его вручную необязательно. Если приложение публикуется через HTTPS, включите secure-cookie: `$env:ONLINE_DEKANAT_HTTPS_ONLY="true"` перед запуском Compose.

Сотрудник может открыть отдельную страницу редактирования профиля из кабинета `/staff/profile`: изменить ФИО и загрузить аватар JPG/PNG/WEBP размером до 2 МБ. Сохранение ФИО и аватара не требует смены пароля: смена пароля вынесена в отдельную форму и кнопку, требует текущий пароль. Почта для входа отображается без возможности редактирования. Переключатель темы доступен на страницах проверки, кабинета и профиля, а выбранная тема синхронизируется между открытыми вкладками. ФИО и аватар хранятся в зашифрованном виде.

На Windows для этих маршрутов и WebSocket-чата используйте FastAPI backend (Docker Compose уже запускает его). Упрощенный backend `simple` чат и учетные записи не поддерживает.

Сборка использует `mirror.gcr.io` для базового образа Python, зеркала Яндекса для Debian и зеркало TUNA для PyPI. Если какой-либо источник недоступен в вашей сети, задайте свои адреса перед сборкой. Например, в PowerShell:

```powershell
$env:PYTHON_BASE_IMAGE = "mirror.gcr.io/library/python:3.11-slim-bookworm"
$env:DEBIAN_MIRROR = "http://mirror.yandex.ru/debian"
$env:DEBIAN_SECURITY_MIRROR = "http://mirror.yandex.ru/debian-security"
$env:PIP_INDEX_URL = "https://pypi.tuna.tsinghua.edu.cn/simple"
docker compose up --build -d
```

Эти переменные передаются в Docker build; `PIP_INDEX_URL` также можно задать перед запуском `setup.bat`. Доступность зеркал зависит от сети и провайдера, поэтому адреса можно заменить на доступные в вашей организации.

Откройте интерфейс <http://localhost:8000/ui>, состояние сервера — <http://localhost:8000/health>, API — <http://localhost:8000/docs>. Чтобы посмотреть журнал контейнера:

```bash
docker compose logs -f web
```

Остановить приложение:

```bash
docker compose down
```

При желании изменить порт задайте `ONLINE_DEKANAT_PORT` перед запуском, например `ONLINE_DEKANAT_PORT=8080 docker compose up --build -d` (в PowerShell: `$env:ONLINE_DEKANAT_PORT=8080; docker compose up --build -d`). Загруженные документы, ключ шифрования, база студентов, JSON-журналы чатов и `results.json` хранятся в именованном Docker volume `app_data` между перезапусками. Не удаляйте volume `app_data`, если нужно сохранить эти данные: вместе с ним удалится и ключ, необходимый для расшифровки документов.

Сборка использует только CPU. Приложение сейчас не использует Ollama или Streamlit: ответы формируются локальной логикой проверки по правилам из `config/regulations.json`.

## Установка и запуск в Windows

### 1. Получите проект

Если проект уже открыт в VS Code, откройте терминал в его корневой папке — там, где находятся `pyproject.toml` и `setup.bat`.

При необходимости клонируйте репозиторий:

```powershell
git clone https://github.com/intropolice/online_dekanat.git
cd online_dekanat
```

### 2. Установите зависимости

Дважды щёлкните `setup.bat` или запустите его из PowerShell:

```powershell
.\setup.bat
```

Скрипт создаёт локальное окружение `.venv`, устанавливает проект и адаптер Tesseract из зеркала PyPI, а также настраивает Tesseract с английскими и русскими языковыми данными. По умолчанию используются `https://pypi.tuna.tsinghua.edu.cn/simple` для Python-пакетов и зеркало Gitee для языковых данных. Источники можно переопределить переменными `PIP_INDEX_URL` и `TESSDATA_SOURCE_URL`. Если Tesseract отсутствует, установщик пытается поставить его через `winget`; пакет `UB-Mannheim.TesseractOCR` загружает установщик из GitHub Releases. Если этот адрес недоступен, установите Tesseract из доступного вам дистрибутива и добавьте `tesseract.exe` в `PATH` либо запустите проект через Docker.

Например, чтобы использовать другое зеркало PyPI:

```powershell
$env:PIP_INDEX_URL = "https://pypi.org/simple"
.\setup.bat
```

После завершения закройте и снова откройте терминал (или VS Code), чтобы применились переменные среды Tesseract.

### 3. Запустите веб-приложение

В новом терминале из корневой папки проекта выполните:

```powershell
.\.venv\Scripts\online-dekanat.exe serve --host 127.0.0.1 --port 8000
```

Откройте в браузере:

- Интерфейс: <http://127.0.0.1:8000/ui>
- Кабинет сотрудника: <http://127.0.0.1:8000/staff>
- Проверка сервера: <http://127.0.0.1:8000/health>
- Интерактивная документация FastAPI: <http://127.0.0.1:8000/docs>, если запущен backend `fastapi`.

В кабинете сотрудника можно включить системные уведомления браузера. Они и звуковой сигнал работают, пока страница открыта; для уведомлений при закрытом сайте нужна отдельная настройка Web Push/VAPID.

Чтобы остановить сервер, нажмите `Ctrl+C` в терминале, где он запущен.

Если порт `8000` занят, укажите другой порт, например:

```powershell
.\.venv\Scripts\online-dekanat.exe serve --host 127.0.0.1 --port 8001
```

### Установка вручную в Windows

Если автоматический установщик использовать нельзя, из корневой папки выполните:

```powershell
$env:PIP_INDEX_URL = "https://pypi.tuna.tsinghua.edu.cn/simple"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip --index-url $env:PIP_INDEX_URL
.\.venv\Scripts\python.exe -m pip install --index-url $env:PIP_INDEX_URL -e ".[tesseract]"
```

Tesseract — отдельная системная программа, её нельзя установить только пакетом `pytesseract`. Например, в Windows её можно установить через `winget`:

```powershell
winget install --id UB-Mannheim.TesseractOCR -e
```

Убедитесь, что Tesseract и языковые данные `rus` и `eng` установлены. При установке языковых файлов вручную задайте `TESSDATA_PREFIX` на каталог `tessdata` и добавьте каталог с `tesseract.exe` в `PATH`. Для запуска в сети, где GitHub недоступен, можно использовать Docker-вариант выше: сборка по умолчанию получает базовый образ, Debian-пакеты и Python-зависимости из настраиваемых источников, а Tesseract устанавливается из зеркала Debian.

## Другие способы запуска

### Командная строка (CLI)

Тестовый пример читает текст непосредственно из `samples/study_certificate.txt`; внешняя OCR-модель для этого не требуется:

```powershell
.\.venv\Scripts\online-dekanat.exe process `
  --file samples/study_certificate.txt `
  --question "Хватит ли справки для перевода на 2 курс?" `
  --ocr text
```

Проверка изображения или PDF с автоматическим выбором OCR:

```powershell
.\.venv\Scripts\online-dekanat.exe process `
  --file "C:\path\to\document.jpg" `
  --question "Подходит ли документ?" `
  --ocr auto
```

Принудительный выбор типа документа и OCR:

```powershell
.\.venv\Scripts\online-dekanat.exe process `
  --file "C:\path\to\application.pdf" `
  --question "Можно оформить академический отпуск?" `
  --doc-type academic_leave_application `
  --ocr tesseract
```

Доступные значения `--ocr`: `auto`, `paddleocr`, `easyocr`, `tesseract`, `text`. Параметр `--doc-type` необязателен. Для `--ocr text` передайте `.txt`-файл с распознанным текстом либо файл, рядом с которым есть файл с таким же именем и расширением `.txt`.

Результат выводится в JSON. Его можно одновременно сохранить в файл:

```powershell
.\.venv\Scripts\online-dekanat.exe process `
  --file samples/study_certificate.txt `
  --question "Хватит ли справки для перевода на 2 курс?" `
  --ocr text `
  --out output/result.json
```

### HTTP API

`POST /process` принимает `multipart/form-data`:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `file` | Да | Файл документа |
| `question` | Да | Вопрос на русском языке |
| `doc_type` | Нет | Идентификатор типа документа; по умолчанию определяется автоматически |
| `ocr` | Нет | `auto`, `paddleocr`, `easyocr`, `tesseract` или `text`; по умолчанию `auto` |

Пример запроса из PowerShell с установленным `curl.exe`:

```powershell
curl.exe -X POST http://127.0.0.1:8000/process `
  -F "file=@samples/study_certificate.txt" `
  -F "question=Хватит ли справки для перевода на 2 курс?" `
  -F "ocr=text"
```

При успешной обработке ответ содержит объект `card` с типом документа, извлечёнными полями и распознанным текстом, а также объект `answer` с текстом ответа, источниками, пропущенными полями и оценкой уверенности. При ошибке API возвращает JSON с полем `error` и HTTP-статус `400`.

Дополнительно ответ содержит `quality` с оценкой снимка и причинами предупреждений, `highlights` со ссылками на PNG-подсветку найденных OCR-областей и `result_id`, который связывает ответ с зашифрованной базой и строкой в `results.json`.

Запись `result_id` в `results.json` служит дополнительным журналом и не влияет на доступность анализа документа. При невозможности обновить журнал приложение сообщает об этом в логе, но всё равно возвращает результат обработки.

Проверка состояния:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

### Запуск через Python-модуль

## OCR и зависимости

Базовые зависимости, необходимые для приложения, устанавливаются вместе с проектом. Дополнительные группы заданы в `pyproject.toml`:

| Набор | Устанавливается как | Для чего нужен |
| --- | --- | --- |
| Основные библиотеки | `pip install -e .` | Веб-приложение, API, PDF, изображения и шифрование |
| Локальный Tesseract | `pip install -e ".[tesseract]"` | Python-адаптер к установленной системной программе Tesseract |
| Все OCR-движки | `pip install -e ".[ocr]"` | PaddleOCR, EasyOCR и Python-адаптер Tesseract |
| Средства разработки | `pip install -e ".[dev]"` | Тесты проекта |
| Работа с датасетом | `pip install -e ".[dataset]"` | Загрузчик MWS-Vision-Bench |

Обычная установка использует только Tesseract и не загружает модели PaddleOCR/EasyOCR:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[tesseract]"
```

Режим `auto` пробует движки в следующем порядке: PaddleOCR → EasyOCR → Tesseract. В стандартной установке доступны только Tesseract и текстовый режим; остальные движки можно добавить через соответствующие extras. Если все установленные движки завершились ошибкой, API/CLI возвращают сообщение об ошибке; текстовый режим автоматически не подставляется.

Для Tesseract нужны и Python-пакет `pytesseract`, и системный исполняемый файл `tesseract`. Для распознавания русского текста также нужны языковые данные `rus`; скрипт установки Windows размещает `eng` и `rus` в пользовательском каталоге и задаёт `TESSDATA_PREFIX`.

Tesseract использует локальные языковые данные и не загружает модель при распознавании. PaddleOCR и EasyOCR могут скачивать модели при первом запуске. Команда `mws-sample` отдельно загружает датасет с Hugging Face; она не нужна для работы приложения.

## Данные и настройки

- Типы документов и шаблоны извлечения полей: `config/document_types.json`.
- Правила проверки и формулировки ответов: `config/regulations.json`.
- Демонстрационный текстовый документ: `samples/study_certificate.txt`.
- API сохраняет исходный загруженный документ в зашифрованном виде в `data/secure/`; расшифрованная копия используется только временно при обработке.
- SQLite-файл `data/students.db` содержит только технический индекс и зашифрованные payload студентов и результатов. Для просмотра локальных записей доступны `GET /students` и `GET /students/{id}/documents`.
- `results.json` в Docker volume `app_data` содержит идентификатор проверки, тип документа, ответ, пропущенные поля и оценку качества снимка для передачи жюри.
- Ключ Fernet создаётся в `data/secure/.storage.key` при первом запуске и не должен публиковаться или передаваться вместе с зашифрованными файлами. Для переноса зашифрованных данных сохраните исходный ключ либо задайте его через `ONLINE_DEKANAT_STORAGE_KEY`.

Каталог `data/` и виртуальное окружение `.venv/` исключены из Git. Не добавляйте ключ хранилища, загруженные документы, токены или другие секреты в репозиторий.

## MWS-Vision-Bench

Опциональная команда `mws-sample` загружает примеры из `MTSAIR/MWS-Vision-Bench` через Hugging Face Datasets и экспортирует выбранные записи в JSONL. Это внешний набор данных для экспериментов, а не источник правил деканата.

Например, экспортировать до 20 примеров задачи OCR:

```powershell
.\.venv\Scripts\online-dekanat.exe mws-sample `
  --limit 20 `
  --task-type "full-page OCR ru" `
  --out data/mws_sample.jsonl
```

Для этой команды нужна группа зависимостей `dataset`. При первом запуске потребуется доступ к Hugging Face и загрузка выбранной части набора.

## Разработка и тесты

Активируйте окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell блокирует запуск `Activate.ps1`, используйте Python и CLI напрямую через `.venv\Scripts\python.exe` и `.venv\Scripts\online-dekanat.exe`, как в примерах выше.

Запуск тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Для запуска FastAPI напрямую через Uvicorn:

```powershell
.\.venv\Scripts\python.exe -m uvicorn online_dekanat.api:app --host 127.0.0.1 --port 8000
```

Если на Windows возникают проблемы с backend Uvicorn, запустите сервер через CLI с `--backend simple`:

```powershell
.\.venv\Scripts\online-dekanat.exe serve --host 127.0.0.1 --port 8000 --backend simple
```

Упрощённый сервер поддерживает веб-форму, `/health` и `/process`; документация OpenAPI `/docs` для него не предоставляется.
